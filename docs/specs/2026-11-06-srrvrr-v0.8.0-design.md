## Goals

Small wins before the big features of v0.9.0 to v0.11.0:
- Always know **which build** is on screen.
- Alerts that say **when** they happened and stay long enough to read.
- An alert **before a drive fills up**.
- Times that stay right across **clock changes and midnight**, proven by tests.

Scope stays ops health. No new fast-loop work: everything new reads what the samplers already collect.

**Less code where it's redundant.** Two of the planned items turned out to duplicate what v0.7.0 already does, so
this design drops them rather than build a second way of doing the same thing (see Decisions).

## Decisions

Made by the owner on 2026-11-06.

| D1 | **Always-shown drives (#64).** The Storage card already shows every fixed drive of 1 GB or more, plus the drive holding the data folder whatever its type, as Missing when it's unplugged (v0.7.0). On the server that covers every drive, including the one removable drive, so a setting to add more would show nothing new. | **#64 closed as not planned.** Reopen it if a drive that isn't fixed and doesn't hold the data folder ever needs watching. |
| D2 | **The recent-alerts list (#63).** v0.7.0's Flagged list already shows the logged events of the last 31 days, newest first, with their times, read from `/events`. | D3 | **Drive-full thresholds.** Used percent, a free-space floor, or both. | **Used percent only:** amber at 85%, red at 95%, both settings. One rule, two settings. At 95%, the smallest drive in use (about 30 GB) still has 1.5 GB free. |
| D4 | **Time format.** The Flagged list and Maintenance use a fixed 24-hour format today (`19:42`). | **12-hour everywhere,** such as `7:42 PM`: banners, the Flagged list (`Nov 6, 7:42 PM`) and Maintenance ("Maintenance until 3:30 PM"). One shared formatter, in the browser's time zone. |

## 1. The version on the page and in /stats (#62)

- **Where the version comes from:** a `VERSION` file in SRRVRR's folder, one line of printable ASCII, at most 64
  characters. The release build already writes it (the tag, such as `v0.8.0`, or `v0.8.0-uat+<commit>` for a UAT
  build). `tools\New-TestBuild.ps1` will write one too: `test-<ref>+<commit>`. With no `VERSION` file (running from a
  clone), the version is `dev`. A file that isn't one valid line reads as `unknown`, and the startup log says why.
- **Read once at startup.** Nothing is read per request.
- **`/stats` gains `version`** (a string). The page shows it in the header after the uptime, such as `v0.8.0`. A
  test or dev build's version is shown in amber, so it can't be mistaken for the installed copy.
- The `VERSION` file is one of SRRVRR's files: the boot launcher's tamper check must list it (see Dependencies).

## 2. Alert times and a 60-second clear (#63)

- **Each banner shows when it happened** (D2): the event's server time (`time`, in milliseconds), in the
  browser's time zone, in 12-hour format (D4), as the banner's last line, such as "7:42 PM". Banners the page makes
  itself, not from an event (such as "More events than shown"), show the time they appeared.
- **One 12-hour formatter** (D4) replaces the two fixed 24-hour ones: banners, the Flagged list and Maintenance all
  use it.
- **Banners close after 60 seconds on screen** instead of 15. The countdown still runs only while the page is
  visible, so a banner that arrives in a background tab is still there when you come back. The close button and
  the limit of four banners on screen stay.
- No new list or button (D2). Counts, not names, in anything kept: unchanged (no player names are logged).

## 3. The drive-almost-full alert (#65)

- **Which drives:** the ones the Storage card shows. Missing drives are skipped.
- **Levels** (D3): `ok`, `filling` (used at or above `DriveWarnPercent`, default 85), `full` (at or above
  `DriveFullPercent`, default 95). A drive goes back down a level only when it's 2 points below that level's
  threshold, so a drive sitting on the line doesn't flap.
- **Events** (new types in the event table):

| Type | Severity | Banner | Logged | When |
|---|---|---|---|---|
| `drive-filling` | warn | yes | yes | A drive reaches `filling` (from `ok`) |
| `drive-full` | flag | yes | yes | A drive reaches `full` |
| `drive-space-ok` | info | no | yes | A drive drops back to `ok` |

  Data: the drive letter, the used percent (whole number) and the free space in GB. No file or folder names.
- **After a start,** the first reading counts as coming from `ok`, so a drive that's already filling or full is
  reported once after each start. (v0.7.0's rule is that the first reading raises nothing; this type is the
  exception, because here the state itself is the alert.)
- **The Storage card's bar** turns amber at `filling` and red at `full`. The server decides the level and sends it as each drive's `level` in `/stats`; the page drops its own fixed 85% and 95%.
- Maintenance silences the banners, as for every event.
- **Settings:** `DriveWarnPercent` and `DriveFullPercent`, whole numbers from 50 to 99, warn below full. Anything
  else is a settings error at startup (exit code 2), with one plain message. Both go in the config example and the
  README's settings table.
- The drive data stays in the slow sampler (every 30 seconds), and the level check runs in the existing event
  detection.

## 4. Clock changes and midnight (#66)

Times inside SRRVRR are kept in two forms. Event times, history timestamps and `ts` are UTC milliseconds, so they
don't move when the clock changes. Daily file names and the `/events?days=n` window use the server's local date.
The tests prove both, with the clock injected (every module already takes a `Clock` or a `Now`) and fixed time
zones that have clock changes:

- **Daily files** (`events-YYYY-MM-DD.jsonl`, `srrvrr-YYYY-MM-DD.log`) roll at local midnight, including on the
  23-hour and 25-hour days. The repeated hour of the fall change writes to the same day's file, in order.
- **`/events?days=n`** starts at local midnight n-1 days back, using that day's own UTC offset. (Read from the
  v0.7.0 code, the window takes today's offset for every day, which is an hour off when the clock changed in
  between. If a test confirms it, it's fixed in this story.)
- **The 31-day retention** ages files by the date in their names, so a clock change neither deletes a day early
  nor keeps one late.
- **History** timestamps stay in order across both changes, and the 15-minute window doesn't jump.
- **The page** shows banner, Flagged list and Maintenance times in the browser's time zone, in 12-hour format,
  tested with fixed zones (the JavaScript tests already pass a time zone), including 12:00 AM and 12:00 PM.
- Midnight: an event at 23:59:59.999 and one at 00:00:00.000 land in their own days' files, and both are found by
  `/events?days=1` and `days=2` as they should be.

## 5. Contract changes

All additions; nothing is renamed or removed, so the pages and scripts that read `/stats` keep working.
- `/stats`: a new `version` field (a string), and a `level` (`ok`, `filling` or `full`) on each drive in `drives`.
- Events: the new types `drive-filling`, `drive-full` and `drive-space-ok` in `/stats` and `/events`. An older
  version reading these log lines shows them by type name (its fallback), so a rollback can still read them.
- Settings: `DriveWarnPercent`, `DriveFullPercent`. An older version warns about them and ignores them, so a
  rollback still starts.
- Files: `VERSION` in SRRVRR's folder.

## 6. Testing, budgets and rollout

- **Tests:** each story adds its test ids to the test plan (`docs/plans/2026-10-29-srrvrr-core-test-plan.md`,
  sections 6 and 7, which the traceability test checks), as T62-, T63-, T65- and T66- ids. The implementation plan
  lists them.
- **Budgets:** as v0.7.0's, against v0.7.0's baseline (`tools\budgets.psd1`): CPU at most 1% on average; memory
  at most 25 MB more; `/stats` p95 at most 30 ms; the page at most 150 ms; startup at most 20 s; disk writes up to
  about 100 MB a day. Nothing here should move them: the new work is a file read at startup and a comparison every
  30 seconds.
- **PRs:** one per story, in this order: #66 (tests first, since any fix lands before the features rely on the
  dates), #62, #63, #65. Each has a UAT doc in `docs/uat/` of about 15 minutes on a test build.
- **Release:** the release PR, the tag v0.8.0 and the GitHub release. Then the boot launcher's release that
  carries v0.8.0, installed by the owner, with an unattended reboot as the finish line.
- **Rollback:** reinstall the previous launcher release, which carries v0.7.0. Section 5 is why that works: v0.7.0
  starts with the new settings in the config and reads the new log lines. Tried once in UAT.

## Dependencies

- **The boot launcher** (a separate private project) pins every SRRVRR file in its tamper check, so its next release
  must list `VERSION` and every other new file, and carries v0.8.0. Tracked in that project.
- **The `/stats` contract** is on record with the other projects that read it (a network test reads `/stats` and
  only needs it to stay JSON). Adding a field is safe.
- **Nothing else changes:** no new ports, firewall rules, accounts or shares.

## Not in this release

- Always-shown drives (#64, closed: D1).
- A separate recent-alerts list, or a header button for the Flagged list (D2).
- A free-space floor for the drive alert (D3).
- Per-drive thresholds.
- Everything planned for v0.9.0 and later: the transfer monitor, 24-hour history, the phone app and a second PC.
