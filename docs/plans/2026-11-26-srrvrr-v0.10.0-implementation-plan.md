# SRRVRR v0.10.0, the workstation: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task,
> in one session (the spec's agent team: one implementer, no subagents, no multi-agent workflows). Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v0.10.0 as four stacked PRs, #89 roles and the host name, #90 video memory and GPU detail, #91
memory detail and top programs, #92 the AI server card, then release it (#93) so a second SRRVRR runs on the dev PC.

**Architecture:** As v0.9.0: logic in `modules\*.psm1` as plain, injectable functions; `SRRVRR.ps1` wires them up.
New: `modules\Workstation.psm1`, pure except one thin HTTP reader (`Read-LocalHttp`), one region per story. A role
plan (`Get-RolePlan`) decides at startup what runs; the Server role runs exactly what v0.9.0 runs. The spill rule
runs in the fast tick (`modules\Counters.psm1`, every second, no new counter read); everything else new runs in the
slow sampler through one call, `Invoke-WorkstationTick`, with its readers passed in.

**Tech Stack:** Windows PowerShell 5.1 (C# 5 inside `Add-Type`), Pester 5, PSScriptAnalyzer, plain JavaScript in
`web\app.js` (tested with `node --test` in CI; Node isn't installed on the dev PC), GitHub Actions on a Windows runner.

**Spec:** `docs/specs/2026-11-26-srrvrr-workstation-design.md` (approved 2026-11-26, Q1 to Q12), on top of the
v0.7.0, v0.8.0 and v0.9.0 designs. **Test plan:** `docs/plans/2026-10-29-srrvrr-core-test-plan.md`, extended by
each story's first task with that story's section from [Appendix A](#appendix-a-test-cases) of this plan (sections
6.14 to 6.17, test ids `T89-` to `T92-`) and its rows in section 7. Executors read the spec, this plan and the
test plan.

**Provisional numbers.** The stories aren't filed as issues yet (the owner's call, 2026-11-26). `#89` to `#93`, the
test ids `T89-` to `T92-` and the branch names assume they become issues #89 to #93. If they get other numbers,
replace each one throughout this plan before Task 1, as one commit.

## Global Constraints

Everything in the v0.9.0 plan's Global Constraints still holds: ASCII-only scripts and modules, PowerShell 5.1 only,
no clock calls in modules, limits as parameters with the design's defaults, settings fail fast with exit 2, no
personal details (no host names other than SRRVRR, documentation-range addresses only, no user-profile paths),
modules loaded by full path, additions only to `/stats`, events, settings and files, lists returned unrolled
(callers write `@(Get-X ...)`). In addition:
- **The Server role is unchanged.** With no `Role` set: `/stats` is v0.9.0's plus `hostName` and `role` only; the
  page looks the same; no new reader, counter read or nvidia-smi field runs.
- **The AI server boundary (spec Q9, section 6).** Only `GET /system_stats` and `GET /prompt`, host the literal
  `127.0.0.1`, 2,000 ms timeout, replies capped at 262,144 bytes, no proxy, no redirects followed. Kept fields only:
  `system.comfyui_version`; the first device's `vram_total`, `vram_free`, `torch_vram_total`, `torch_vram_free`;
  `exec_info.queue_remaining`. Nothing is relayed. No `wsl.exe`, ever.
- **No names from the AI server:** never prompts, model names, file names or previews. Event data holds counts,
  durations and the owner's configured entry names only.
- **Nothing new needs administrator.** Every Workstation reader works unelevated.
- **Fixed values, as parameters with these defaults:** spill start 95% and 1 GiB for 10,000 ms; spill end below
  90% or below 0.5 GiB for 30,000 ms; job minimum 60 s; not answering after 3 misses; startup probe timeout
  1,000 ms; top programs 5 by video memory plus 5 by RAM, at most 8 rows; `.wslconfig` re-read every 60,000 ms;
  WSL and commit amber at 90%; `ComfyUi` at most 4 entries.
- **Units in `/stats`:** bytes for every memory and size; bytes per second for `memPageIn`; whole watts, MHz and
  fan percent; CPU percent of the whole machine with one decimal; seconds for `workingSec` and `lastDoneSec`;
  milliseconds since 1970 for `lastDoneTs`. History lines `vram` and `vramShared` are GiB with two decimals.
- **Tests first,** and every Pester `It` starts with its id.
- **Budgets** (spec section 13): the Server role against `tools\budgets.psd1` (v0.9.0's baseline); the Workstation
  against `tools\budgets.workstation.psd1`, created in #89. Numbers go in each PR's description.
- **Decision lines** go in `docs/DECISIONS.md`, which is local-only (`AGENTS.md`): never commit it.

### Region 90: video memory and GPU detail

```powershell
function Get-SmiArguments { param([ValidateSet('clocks_event_reasons', 'clocks_throttle_reasons')][string]$Prefix) }
# -> @('--query-gpu=name,temperature.gpu,power.draw,power.limit,clocks.sm,clocks.max.sm,fan.speed,pstate,' +
#      "$Prefix.sw_power_cap,$Prefix.hw_slowdown,$Prefix.sw_thermal_slowdown,$Prefix.hw_thermal_slowdown,$Prefix.hw_power_brake_slowdown",
#      '--format=csv,noheader,nounits')
function Select-SmiPrefix { param([hashtable]$Event, [hashtable]$Throttle) }   # each @{ Lines = [string[]]; ExitCode = [int] } or $null
# -> 'clocks_event_reasons' | 'clocks_throttle_reasons' | 'none'
function ConvertFrom-SmiDetail { param([string[]]$Lines, [string]$GpuName) }
# -> @{ gpuTemp; gpuPower; gpuPowerLimit; gpuClock; gpuClockMax; gpuFan; gpuPState; gpuLimits } or $null
function Get-WorkstationEvents { param([object]$Old, [object]$New) }   # -> records @{ Type; Data; Key }, as Get-BurstEvents returns
```

- `Select-SmiPrefix` gives the event prefix when its query exited 0, the throttle prefix when the event query failed
  with a line matching `is not a valid field to query` and the throttle query exited 0, else `none`. SRRVRR.ps1 runs
  the queries once at startup on the main thread; with `none` the slow sampler keeps today's
  `--query-gpu=name,temperature.gpu` call.
- In `ConvertFrom-SmiDetail`, the line is the one whose first field equals `GpuName`, or the only line, as today. A
  field that is `[N/A]`, empty, `Not Supported` or not a number is `$null`. Temperature is `[int]` of the reading, as
  today. Power is a whole number of watts, clocks MHz, fan percent, and `gpuPState` the text (`P2`). `gpuLimits` is a
  list in this order, without repeats: `'power'` (sw_power_cap or hw_power_brake_slowdown `Active`), `'thermal'`
  (either thermal reason `Active`), `'slowed'` (hw_slowdown `Active`).
- `Get-WorkstationEvents` here covers the spill: `gpuSpill` `$false` to `$true` gives `vram-spill`, with `Data`
  `@{ dedicatedGb; sharedGb }` (one decimal) and `Key` `'vram-spill'`; `$true` to `$false` gives `vram-spill-ended`,
  `Key` `'vram-spill-ended'`. Old `$null`, or `gpuSpill` missing on either side, gives nothing. #92 adds the AI part.

In `modules\Counters.psm1`:

```powershell
function New-SpillWatch { }   # -> @{ Spilling = $false; SinceMs = $null; LastMs = $null }
function Update-SpillWatch {
    param([hashtable]$Watch, [double]$Dedicated, [double]$Total, [double]$Shared, [long]$NowMs,
          [double]$StartPercent = 95, [double]$StartShared = 1GB, [int]$StartMs = 10000,
          [double]$EndPercent = 90, [double]$EndShared = 512MB, [int]$EndMs = 30000)
}   # -> [bool] Spilling, updating $Watch
New-FastTickContext ... [bool]$Workstation = $false, [double]$GpuTotal = 0   # adds Workstation, GpuTotal, Spill = (New-SpillWatch)
```

Update-SpillWatch works like this:
- While not spilling, the start condition is `Total -gt 0` and `Dedicated -ge Total * StartPercent / 100` and
  `Shared -ge StartShared`.
- While spilling, the end condition is `Dedicated -lt Total * EndPercent / 100` or `Shared -lt EndShared`.
- A true condition starts `SinceMs` if it's `$null`. The state flips when `NowMs - SinceMs` reaches the hold time,
  and then `SinceMs` goes back to `$null`.
- A false condition resets `SinceMs`.
- `NowMs` below `LastMs` (the clock went back) resets `SinceMs`.
- `Total` of 0 or less forces not spilling.

On a Workstation context, `Invoke-FastTick` also:
- sets `$State.gpuShared` with `Get-GpuMemory` on `'GPU Adapter Memory' 'Shared Usage'` (same LUID filter);
- sets `$State.gpuSpill` from `Update-SpillWatch`;
- appends `vram` and `vramShared`, `[math]::Round($bytes / 1GB, 2)`.

On a Server context, none of these three happen.

### Region 91: memory detail and top programs

```powershell
function Get-MemoryDetail { param($Previous, $Current, [int]$PageSize = 4096) }
# -> @{ memCommit = [long]; memCommitLimit = [long]; memPageIn = [long] or $null (no Previous) }
function ConvertFrom-WslConfig { param([string]$Text, [double]$TotalRam) }   # -> @{ Cap = [double]; Source = 'config'|'default' }
function Get-WslReading { param([object]$Process, [hashtable]$Cap) }   # -> @{ running; mem; cap; capSource }
function Get-TopPrograms {
    param($Previous, $Current, [double]$ElapsedSeconds, [int]$Cores, [string]$GpuLuid, [int]$Count = 5, [int]$MaxRows = 8)
}   # -> rows @{ name; count; vram; mem; cpu }
function New-WorkstationContext {
    param([object[]]$ComfyEntries = @(), [string]$GpuLuid, [int]$Cores, [double]$TotalRam, [int]$PageSize = 4096,
          [hashtable]$Readers, [int]$WslConfigEveryMs = 60000)
}   # -> @{ ...the parameters...; Previous = $null; PreviousMs = $null; WslCap = $null; WslCapReadMs = $null; Ai = (New-AiWatch ...) }
function Invoke-WorkstationTick { param([hashtable]$State, [hashtable]$Context, [long]$NowMs) }
```

- `$Readers` keys:
  - `Counters`: a scriptblock returning a snapshot of `Memory`, `Process` and `GPU Process Memory`, each category
    missing if it doesn't exist.
  - `WslProcess`: `Get-Process -Name vmmemWSL -ErrorAction SilentlyContinue | Select-Object -First 1`.
  - `WslConfig`: the text of `$env:USERPROFILE\.wslconfig`, or `$null`.
  - `Http`: `param($Port, $Path)` calling `Read-LocalHttp`; added in #92.
- **What `Invoke-WorkstationTick` sets:** `memCommit`, `memCommitLimit`, `memPageIn`, `wsl`, `top`, and in #92 `ai`.
  Each part is in its own `try`/`catch`. A failure sets `$State.workstationError = '<part>: <message>'`, with the
  parts named `memory`, `wsl`, `top programs` and `ai server`. The other parts still run. A pass where every part
  succeeds clears it.
- **In `ConvertFrom-WslConfig`:**
  - It reads `memory=` in the `[wsl2]` section, in any case and with spaces around `=`. A `#` starts a comment.
  - The value is a number, decimals allowed, with `KB`, `MB`, `GB` or `TB` (1024-based, any case). Anything else, or
    no file, gives `TotalRam / 2` with Source `default`.
- **Get-TopPrograms, building the programs:**
  - The program is the `Process` instance name without a final `#<digits>`, so `my#app#1` becomes `my#app`.
  - `_Total` and `Idle` are dropped, and `vmmemWSL` is named `WSL VM`.
  - RAM is `Working Set - Private`. Video memory is `GPU Process Memory` `Dedicated Usage` for instances of `GpuLuid`,
    matched to a program by the pid in the instance name and `ID Process`.
  - CPU is the `% Processor Time` delta divided by `Cores`, one decimal. It is `$null` when there is no Previous,
    when the instance is new, or when its `ID Process` changed between the readings.
- **Get-TopPrograms, choosing the rows:** the union of the top `Count` by video memory (above 0) and the top `Count`
  by RAM, sorted by video memory, then RAM, both descending, then cut to `MaxRows`.

### Region 92: the AI server

```powershell
function Read-LocalHttp {
    param([ValidateRange(1024, 65535)][int]$Port, [ValidateSet('/system_stats', '/prompt')][string]$Path,
          [int]$TimeoutMs = 2000, [int]$MaxBytes = 262144)
}   # -> @{ Ok = [bool]; Status = [int]; Body = [string]; Error = [string] }
function ConvertFrom-ComfyStats { param([string]$Body) }   # -> @{ version; vramTotal; vramFree; holds; torchFree } or $null
function ConvertFrom-ComfyQueue { param([string]$Body) }   # -> [int] or $null
function New-AiWatch { param([object[]]$Entries) }         # -> @{ <name> = @{ State; Misses; AnsweredThisVm; AnsweredWithVm; WorkingSinceMs; LastDoneTs; LastDoneSec; LastRow; VmWas } }
function Update-AiWatch {
    param([hashtable]$Watch, [string]$Name, [hashtable]$Answer, [object]$VmRunning, [long]$NowMs,
          [int]$MinJobSec = 60, [int]$MissesToFail = 3)
}   # $Answer = @{ Ok; Stats; Queue }; $VmRunning $true / $false / $null (can't tell)
# -> row @{ name; state; queue; workingSec; holds; vramTotal; vramFree; version; lastDoneTs; lastDoneSec }
```

- **Read-LocalHttp** uses `[Net.HttpWebRequest]::Create('http://127.0.0.1:' + $Port + $Path)` with:
  - `Method = 'GET'`, `Timeout` and `ReadWriteTimeout = $TimeoutMs`;
  - `Proxy = $null`, `AllowAutoRedirect = $false`, `KeepAlive = $false`.

  It reads at most `MaxBytes + 1` bytes as UTF-8. More than `MaxBytes` means `Ok = $false` with Error
  `reply too large`. A status other than 200, a timeout or a refusal also means `Ok = $false`. Nothing else in the
  module does network I/O.
- **The states** are `off`, `starting`, `idle`, `working`, `not-answering` and `unknown`. Answered means `Ok`, with
  `Stats` and `Queue` both non-null. `Ok` with either one `$null` is `unknown`, and `unknown` counts as answering.
- **The order of the rules:**
  1. A `VmRunning` change from `$false` to `$true` resets `AnsweredThisVm`.
  2. Answered: `Misses = 0`, `AnsweredThisVm = $true`, `AnsweredWithVm = ($VmRunning -eq $true)`.
     - A queue of 1 or more starts `WorkingSinceMs` (if `$null`), and the state is `working`.
     - A queue of 0 is `idle`. When `WorkingSinceMs` was set and at least `MinJobSec` has passed, it sets
       `LastDoneTs = NowMs` and `LastDoneSec`. Then `WorkingSinceMs = $null`.
  3. Not answered, with `VmRunning -eq $false` and `AnsweredWithVm`: the VM it ran in has gone, so the state is
     `off` at once. `WorkingSinceMs`, `AnsweredThisVm` and `AnsweredWithVm` are cleared.
  4. Not answered otherwise: `Misses++`. While the last state was `idle`, `working` or `unknown` and
     `Misses -lt MissesToFail`, the last row is held. This covers a ComfyUI that runs on Windows itself, with no VM:
     it gets the miss rule, not rule 3.
  5. After that, the state is `not-answering` if `AnsweredThisVm` (and `WorkingSinceMs` is cleared). Otherwise it
     is `starting` when `VmRunning -eq $true`, and `off` when it isn't.
  6. `workingSec` is `[math]::Max(0, NowMs - WorkingSinceMs) / 1000`, rounded. A clock that went back never gives a
     negative time.
- `Invoke-WorkstationTick` asks each entry for `/system_stats`, then `/prompt` only if the first was `Ok`, so a
  tick makes at most 2 calls per entry. It then sets `$State.ai` to a new array of rows each tick.
- `Get-WorkstationEvents` gains the AI part:
  - For each row by `name`: old `working` and new `not-answering` gives `ai-stopped-answering`, with `Data`
    `@{ name }` and `Key` `"ai-stopped-answering|$name"`.
  - A non-null new `lastDoneTs` that differs from the old one gives `ai-job-done`, with `Data` `@{ name; seconds }`
    and `Key` `"ai-job-done|$name|$lastDoneTs"`. The key is unique, so the 10-minute repeat rule never hides a
    second batch.

### Points the spec left open, settled here

- `gpuMemTotal` joins `/stats` (Workstation only), so the page can scale the tile.
- The spill rule runs in the fast tick: it needs every second, and it reads only the `GPU Adapter Memory` snapshot
  the tick already has.
- Memory detail, WSL and top programs read their own `Memory`, `Process` and `GPU Process Memory` snapshot every
  5 s in the slow sampler, as the spec's section 9 says. That keeps the fast tick at v0.9.0's cost.
- The nvidia-smi prefix is chosen once at startup on the main thread (`Select-SmiPrefix`), with its log line there.
- The startup log line per AI server entry comes from one probe on the main thread (`Read-LocalHttp -TimeoutMs 1000`).
- `/prompt` is skipped when `/system_stats` failed, which bounds a hung AI server to 2 s per entry per pass.
- `workstationError` joins Invoke-Watch's watched keys (`'error', 'drivesError', 'tempError', 'transfersError'`).
- The WSL process is `vmmemWSL` only (the older `vmmem` is shared with Hyper-V machines).
- A ComfyUI that runs on Windows itself, with no WSL VM (the spec assumes WSL), still gets "Not answering" after 3
  misses. A VM that isn't running only means Off for an entry that last answered while the VM was up (region 92, rule 3).
- The workstation budget is a separate file, `tools\budgets.workstation.psd1`, so `Measure-SRRVRR.ps1` needs no change.

1. **The clock jumps** (daylight saving, a manual change) during a spill hold or a job: no negative or huge times,
   and holds restart. Pinned by T90-04 and T92-10.
2. **HTML in a program name or a ComfyUI string** (a process named `<img src=x onerror=alert(1)>`, a version string
   with `<script>`) shows as text. Pinned by T91-10 and T92-15.
3. **A Workstation with no NVIDIA card, or no GPU counters** (a laptop with built-in graphics): the Video memory
   tile says n/a, there is no spill, the GPU line is today's, and nothing errors. Pinned by T90-01 and T90-12.
4. **The AI server accepts connections but never replies,** on both entries: each slow pass is bounded (at most
   2 s per entry), and the other slow checks still run every pass. Pinned by T92-03, T92-13 and T92-18.
5. **Programs come and go between readings** (a game exiting, a reused process id): no wrong CPU numbers and no
   exception. Pinned by T91-05.
