# SRRVRR v0.9.0, the transfer monitor: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v0.9.0 as four stacked PRs: the bottleneck and the shares (#76), write bursts (#77), PCs and folders
(#78), and Maintenance limited to named PCs (#79). Four builders work **in parallel**, one per story, each in its own
worktree off `feature/v0.9.0-plan`; the lead stacks them afterwards (#76 <- #77 <- #78 <- #79).

**Architecture:** As v0.8.0: logic in `modules\*.psm1` as plain, injectable functions; `SRRVRR.ps1` wires them up.
New: `modules\Transfers.psm1` (pure: no clock, counter, CIM or file calls, test plan 3.2). The SMB counters, the CIM
session and open-file lists and `Win32_Share` are all read in the slow sampler (the SMB, network and disk counters
every 5 s: design Q1, decided 2026-11-11; the fast loop stays as v0.8.0 has it); one synchronized table, the **transfer monitor**, carries what the two samplers and the web server share.

**Tech Stack:** Windows PowerShell 5.1, Pester 5, PSScriptAnalyzer, plain JavaScript in `web\app.js` (tested with
`node --test` in CI), GitHub Actions on a Windows runner.

**Spec:** `docs/specs/2026-11-07-srrvrr-v0.9.0-design.md` (its Q1 to Q12 decisions, as the owner made them on 2026-11-11), on
top of the v0.7.0 and v0.8.0 designs. **Test plan:** `docs/plans/2026-10-29-srrvrr-core-test-plan.md`, extended
with sections 6.10 to 6.13 (test ids `T76-` to `T79-`) and their rows in section 7. Executors read all three.

## Global Constraints

Everything in the v0.8.0 plan's Global Constraints still holds (ASCII scripts, 5.1 only, no clock calls in modules,
limits as parameters, settings fail fast with exit 2, no personal details, modules by full path, additions only to
`/stats`, events, settings and files). In addition:
- **Folders and counts, never file names** (design section 3). A file name is dropped as soon as it's read; no
  structure, `/stats` field or log line ever holds one. Canary file names in the fixtures prove it (T78-05).
- **Addresses only** for PCs (Q3); no name lookups anywhere.
- **The account is logged in the four new event types only** (Q8's exception to SEC3), under the data key
  `account`. Every other event keeps dropping user names (`ConvertTo-LoggedEvent` is unchanged).
- **Bounds as parameters with the design's defaults:** 64 PCs, 32 shares, 10 folders per PC, 5 folders per burst
  event, 5,000 open files per sample, folder depth 3 and 120 characters, the 1 MB/s idle floor (`1MB`), the 2 s
  hold, ended bursts kept 120 s for the watcher.
- **Lists come back unrolled:** callers write `@(Get-X ...)`; functions return their items (an empty list is
  nothing), never `, @()`.
- **Fixtures** use made-up share names, accounts and paths, documentation-range addresses (`192.0.2.x`,
  `2001:db8::`), and arbitrary drive letters (test plan 8.1).
- **Budgets** against v0.8.0's baseline in `tools\budgets.psd1`, measured on each PR's test build with
  `tools\Measure-SRRVRR.ps1`, numbers in the PR description (design section 9): the fast tick against its budget, and
  the slow sampler's own time per pass (`slowMs`, median and max) as well (Q1).

```powershell
# The Transfers card (docs/specs/2026-11-07-srrvrr-v0.9.0-design.md): the bottleneck, the shares, PCs and folders,
# write bursts. Pure functions: no clock, counter, CIM or file calls; callers pass readings and times in. One region
# per story (docs/plans/2026-11-10-srrvrr-v0.9.0-implementation-plan.md, Shared interfaces): change only your own.
# Every function is exported (no Export-ModuleMember), so the regions never share a line.
Set-StrictMode -Version 2

#region Shared (byte-identical in every branch; only the lead changes it)
# What the samplers and the web server share: one synchronized table, given to both runspaces.
function New-TransferMonitor {
    param([hashtable]$Settings = @{}, [bool]$Elevated, [string[]]$ServerAddresses = @())
    $get = { param($k, $d) if ($Settings.ContainsKey($k) -and $null -ne $Settings[$k]) { $Settings[$k] } else { $d } }
    [hashtable]::Synchronized(@{
        Elevated = $Elevated; ServerAddresses = @($ServerAddresses); BottleneckPercent = [int](& $get 'BottleneckPercent' 80)
        BurstFiles = [int](& $get 'BurstFiles' 500); BurstWindowSeconds = [int](& $get 'BurstWindowSeconds' 60)
        BurstQuietMinutes = [int](& $get 'BurstQuietMinutes' 5); TransferFolders = [bool](& $get 'TransferFolders' $true)
        NamedIndex = (New-NamedPcIndex -NamedPCs @(& $get 'NamedPCs' @()))
        Shares = @(); SessionPcs = @{}; PcFolders = @{}; OpenFilesCapped = $false; UpdatedMs = $null; Busy = $false
        Hold = @{ Shown = 'idle'; Candidate = 'idle'; SinceMs = 0L }; Bursts = @{}; BurstList = @(); UnknownSeen = @{}
    })
}
# An address as SRRVRR compares it: IPv4-mapped IPv6 back to IPv4, brackets and the zone id dropped, IPv6 in lower
# case. $null for anything that isn't an address.
function ConvertTo-PcAddress {
    param([string]$Address)
    if (-not $Address) { return $null }
    $text = ($Address.Trim() -replace '^\[|\]$', '') -replace '%.*$', ''
    $ip = $null
    if (-not [Net.IPAddress]::TryParse($text, [ref]$ip)) { return $null }
    if ($ip.IsIPv4MappedToIPv6) { $ip = $ip.MapToIPv4() }
    $ip.ToString().ToLowerInvariant()
}
# Address (as ConvertTo-PcAddress gives it) -> the named PC's Name, from the NamedPCs setting.
function New-NamedPcIndex {
    param([object[]]$NamedPCs = @())
    $index = @{}
    foreach ($pc in $NamedPCs) {
        if ($pc -isnot [Collections.IDictionary]) { continue }
        foreach ($a in @($pc['Addresses'])) { $k = ConvertTo-PcAddress ([string]$a); if ($k) { $index[$k] = [string]$pc['Name'] } }
    }
    $index
}
# Who an address is: @{ Address; Name; Known; Self }. Self: loopback or one of ServerAddresses (the server itself is
# always trusted). Known: Self, or in the index. Name: the named PC's Name, else $null.
function Find-NamedPC {
    param([string]$Address, [hashtable]$Index = @{}, [string[]]$ServerAddresses = @())
    $a = ConvertTo-PcAddress $Address
    $out = @{ Address = $a; Name = $null; Known = $false; Self = $false }
    if (-not $a) { return $out }
    $self = [Net.IPAddress]::IsLoopback([Net.IPAddress]::Parse($a))
    foreach ($s in $ServerAddresses) { if (-not $self -and (ConvertTo-PcAddress $s) -eq $a) { $self = $true } }
    if ($self) { $out.Known = $true; $out.Self = $true; return $out }
    if ($Index -and $Index.ContainsKey($a)) { $out.Name = $Index[$a]; $out.Known = $true }
    $out
}
#endregion Shared

#region 76 The bottleneck and the shares (#76)
#endregion 76

#region 77 Write bursts (#77). Stubs until #77 lands: no bursts, no events.
function Update-WriteBursts { param([hashtable]$State, [object[]]$Pcs, [object[]]$Shares, [long]$NowMs, [int]$Files, [int]$WindowSeconds, [long]$QuietMs) }
function Get-BurstEvents { param([object[]]$Old, [object[]]$New, [object[]]$PcRows, [hashtable]$PcFolders, [bool]$IncludeFolders, [long]$StopMs) }
#endregion 77

#region 78 PCs and folders (#78). Stubs until #78 lands: no PCs, no events.
function Get-SessionPcs { param([object[]]$Sessions, [object[]]$OpenFiles, [object[]]$Shares, [hashtable]$Index, [string[]]$ServerAddresses, [bool]$Folders, [int]$MaxOpenFiles = 5000) @{ SessionPcs = @{}; PcFolders = @{}; Capped = $false } }
function Get-TransferPcRows { param([object[]]$Pcs, [hashtable]$SessionPcs, [hashtable]$PcFolders, [object[]]$Bursts, [int]$MaxPcs = 64) }
function Get-UnknownPcEvents { param([hashtable]$Seen, [object[]]$PcRows, [bool]$Elevated) }
#endregion 78

#region 79 (none: #79's code is in Maintenance.psm1, Web.psm1 and web\app.js)
#endregion 79
```

**Who calls what at runtime** (all wiring is #76's, so #77 and #78 never touch `SRRVRR.ps1`):
- Slow sampler, every pass (5 s, design Q1): it reads `SMB Server Shares`, `SMB Server Sessions`, `Network Interface`
  and `LogicalDisk` itself (read once before its loop, so the first pass has a previous reading) and calls
  `Invoke-TransferTick` (#76) with `Get-SmbCounterReading`. That works out the seconds since its last call (1 to
  60, `Monitor.LastTickMs`), calls `Group-SessionsByPc`, `Get-Bottleneck`, `Update-WriteBursts -Seconds` (#77),
  `Get-TransferPcRows` (#78) and `New-TransfersSnapshot`, sets `$state.transfers` and `Monitor.BurstList`,
  `Monitor.Busy`, and appends `smbRead` and `smbWrite` to the history for each of those seconds. The pass's own time
  goes to `$state.slowMs`. The fast loop reads no SMB counters.
- Slow sampler: `Invoke-TransferSample -Monitor -Tick -NowMs -Readers` (#76) every 5 s tick: the share list at tick
  0 and every 12th; elevated only, `Get-SessionPcs` (#78, with `Monitor.Shares`, `Monitor.NamedIndex`,
  `Monitor.ServerAddresses` and `Monitor.TransferFolders`) every tick while `Monitor.Busy`, else every 6th. Readers
  are built inside the slow runspace: `@{ Shares = { Get-ShareList }; Sessions = { Get-SmbSessionList }; OpenFiles =
  { Get-SmbOpenFileList } }` (the last two are #78's, in `DataFolder.psm1`; until #78 lands the stub never calls
  them). An error goes to `$state.transfersError`.
- Main loop, `Invoke-Watch`, once a second: `Get-BurstEvents -Old $script:lastBursts -New $transferMonitor.BurstList`
  and `Get-UnknownPcEvents`, each record raised with `Add-SrrEvent`; a stop saver calls `Get-BurstEvents -StopMs`
  (reason `stopped`), and `Exit-SRRVRR`'s drain writes them.
- Web: `Context.Viewer` (#79) calls `Find-NamedPC` with `Context.NamedIndex` and the Host check's addresses.

### Points the design left open, settled here

- **Test ids** are `T76-` to `T79-` (the issues), not the design's `T21a-` to `T21d-`.
- **Signing and encryption** come from the open files: `MSFT_SmbSession` has neither (checked on the server's CIM
  schema), `MSFT_SmbOpenFile` has both. Open files carry no share name either, so a file's share is found from its
  `Path` and the share list.
- **`viewer` gains `address`** (additive): the page's Q9 message names the address the server saw.
- **The account** is logged in all four new event types (Q8 says "the four flag events", but `unknown-pc` is a
  warning; its data in section 4 includes the account).
- **About 6 KB** holds for a few PCs; with every bound full `transfers` is far larger, so T78-20 measures `/stats`
  then. If it breaks the 30 ms p95, #78 stops and asks the lead; the bounds don't change silently.
- **`reason`** is one string: counters missing, then needs administrator, then more than 5,000 open files, else null.
