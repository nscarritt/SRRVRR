# SRRVRR v0.8.0, alerts and drives: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v0.8.0 as four stacked PRs: clock-change and midnight tests (#66), the version on the page and in
`/stats` (#62), alert times in a 12-hour format with a 60-second clear (#63), and the drive-almost-full alert (#65).

**Architecture:** As v0.7.0: logic in `modules\*.psm1` as plain, injectable functions; `SRRVRR.ps1` wires them up.
Nothing new runs in the 1 s loop. The version is read once at startup; drive levels are worked out in the slow
sampler and compared in the existing event detection.

**Tech Stack:** Windows PowerShell 5.1, Pester 5, PSScriptAnalyzer, plain JavaScript in `web\app.js` (tested with
`node --test` in CI), GitHub Actions on a Windows runner.

**Spec:** `docs/specs/2026-11-06-srrvrr-v0.8.0-design.md`, on top of `docs/specs/2026-10-28-srrvrr-core-design.md`.
**Test plan:** `docs/plans/2026-10-29-srrvrr-core-test-plan.md`, which this plan extends with sections 6.6 to 6.9
(test ids `T62-`, `T63-`, `T65-`, `T66-`) and their rows in section 7. Executors read all three.

## Global Constraints

Everything in the v0.7.0 plan's Global Constraints still holds (ASCII scripts, 5.1 only, no clock calls in modules,
limits as parameters, settings fail fast with exit 2, no personal details, modules by full path). In addition:
- **Additions only** to `/stats`, events, settings and files (spec section 5). No field, route, setting or event
  type is renamed or removed.
- **One time formatter** on the page (`fmtTime`), 12-hour, in the browser's time zone (or the one a test passes).
  No `en-GB` or `h23` is left in `web\app.js`.
- **One source for drive levels:** the server decides `ok`, `filling` and `full`; the page only colors by it.
- **Counts, not names,** in every new event's data: the drive letter, the used percent and the free GB.
- **Budgets** against v0.7.0's baseline in `tools\budgets.psd1`, measured on each PR's test build with
  `tools\Measure-SRRVRR.ps1`, numbers in the PR description.

## How to run things

As in the v0.7.0 plan: `powershell -NoProfile -ExecutionPolicy Bypass -File tools\Invoke-Checks.ps1` (add
`-Path tests\<Name>.Tests.ps1` for one file). Node isn't installed on the server, so the JavaScript tests run in CI:
push the branch and read the run before asking for UAT. Test builds:
`tools\New-TestBuild.ps1 -Ref <branch> -Destination <test folder> -Port 8091`. Each task follows the same cycle:
failing tests first, see them fail, implement, see them and the whole suite pass, commit.

Branches stack in order: `feature/66-clock-tests` <- `feature/62-version` <- `feature/63-alert-times` <-
`feature/65-drive-full`. Each PR targets the branch before it; after a merge, the next one is rebased onto `main`.

**Tests:** T66-01 to T66-04, T66-06.

### Task 2: The `/events` window, using each day's own offset

The v0.7.0 window starts at `[DateTimeOffset]::new($Now.Date.AddDays(-($Days - 1)), $Now.Offset)`: today's offset for
every day, which is an hour off when the clock changed in between. T66-05 shows it first.

**Files:**
- Modify: `modules\EventLog.psm1` (`Get-IndexedEvents` and the loader's first-day date take a `[TimeZoneInfo]`
  parameter, default `[TimeZoneInfo]::Local`, and find local midnight with `TimeZoneInfo.ConvertTimeToUtc`),
  `SRRVRR.ps1` (passes nothing: the default is right)
- Test: `tests\Clock.Tests.ps1`, `tests\EventLog.Tests.ps1` (existing tests still pass)

**Tests:** T66-05, T66-08.

### Task 3: History timestamps across the fall change

**Files:** Test: `tests\Clock.Tests.ps1`. Modify `modules\History.psm1` only if T66-07 fails.

**Tests:** T66-07.

- [ ] **PR for #66:** CHANGELOG `[Unreleased]` ("Fixed" if Task 2 changed code, else "Added: tests"), push, open the
